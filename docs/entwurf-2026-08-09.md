# SignalForge — Entwurf

**Stand:** 09.08.2026 · **Status:** zur Abnahme durch Max

> Arbeitsdokument auf Deutsch. Die öffentlichen Dokumente des Projekts (README,
> ARCHITECTURE) entstehen auf Englisch in der Veröffentlichungsstufe.

---

## 1. Worum es geht

SignalRGB kann Beleuchtungseffekte nur abspielen, nicht bauen. Wer einen eigenen Effekt
will, muss eine HTML-Datei von Hand schreiben. Die zwei Werkzeuge, die es dafür in der
Gemeinschaft gibt, können ausschließlich geometrische Formen — **eigene Bilder oder
Videos als Beleuchtung gibt es nirgends.**

SignalForge schließt diese Lücke: ein Desktop-Programm, mit dem man aus Bildern, Videos,
Verläufen und Formen einen SignalRGB-Effekt zusammenstellt, live sieht was herauskommt,
und ihn per Knopfdruck installiert.

### Wie SignalRGB Effekte liest

Ein Effekt ist eine Webseite mit einer Zeichenfläche von 320 × 200 Pixeln. SignalRGB legt
das Geräte-Layout darüber und liest an jeder LED-Position die Farbe ab. Regler in der
SignalRGB-Oberfläche entstehen aus `<meta property="…">`-Angaben im Kopf der Datei und
liegen zur Laufzeit als JavaScript-Variablen gleichen Namens vor.

Die Datei muss im Effektordner liegen, üblicherweise
`%USERPROFILE%\Documents\WhirlwindFX\Effects`.

## 2. Festgelegte Entscheidungen

| Punkt | Entscheidung | Begründung |
|---|---|---|
| Name | **SignalForge** | Von Max gewählt. Markennähe zu „SignalRGB" ist bekannt — siehe Risiko R5. |
| Lizenz | **GPLv3** | Verhindert, dass jemand daraus ein geschlossenes Bezahlprodukt macht. |
| Code | **Englisch** (Bezeichner, Kommentare, Commits) | Damit fremde Mitbauer mitlesen können. |
| Oberfläche | **Deutsch + Englisch**, umschaltbar, Standard = Systemsprache | Max und seine Freunde auf Deutsch, alle anderen auf Englisch. |
| Technik | **Electron** | Siehe unten. |
| Plattform | **Nur Windows** | SignalRGB gibt es nur für Windows. Keine künstlichen Hürden für andere Systeme einbauen, aber auch nicht dafür testen. |
| Optik | Glassmorphism | Von Max vorgegeben. |

### Warum Electron

Der ausschlaggebende Grund: **SignalRGB-Effekte laufen in Chromium, und Electron ist
Chromium.** Die Vorschau läuft damit im selben Motor wie der fertige Effekt — inklusive
derselben Video-Codecs. Bei Tauri oder einem Python-Fenster liefe die Vorschau in Edge
WebView2, also einem anderen Chromium-Bau. Meist identisch, aber nicht garantiert.

Dazu: Der Effekt **muss** JavaScript sein, das gibt SignalRGB vor. Mit Electron ist die
App ebenfalls JavaScript — eine Sprache für alles, und die Engine wird wirklich geteilt
statt nachgebaut. Wer an einem SignalRGB-Werkzeug mitbauen würde, kann ohnehin HTML/JS.

Verworfen: **Tauri** (10 MB statt 150 MB, aber Rust und falscher Browser),
**Python + Fenster** (zwei Sprachen, Engine müsste doppelt existieren).

Preis: rund 150 MB Installationsgröße.

## 3. Aufbau

Drei Teile, klar getrennt:

```
┌─────────────────────────────────────────────────────────┐
│  Hauptprozess (Electron, Node)                          │
│  Dateien lesen/schreiben · ffmpeg aufrufen ·            │
│  Effektordner finden · Einstellungen                    │
└──────────────────────┬──────────────────────────────────┘
                       │  schmale, festgelegte Schnittstelle
┌──────────────────────┴──────────────────────────────────┐
│  Oberfläche (Fenster)                                   │
│  Ebenenliste · Vorschau · Einstellungen · Export        │
│                                                          │
│      ┌────────────────────────────────────┐             │
│      │  engine/  ← rendert das Dokument   │             │
│      └────────────────────────────────────┘             │
└─────────────────────────────────────────────────────────┘
                       │  dieselben Dateien werden eingebettet
┌──────────────────────┴──────────────────────────────────┐
│  Exportierter Effekt (.html im SignalRGB-Ordner)        │
│  engine/ + Dokument + Meta-Regler                       │
└─────────────────────────────────────────────────────────┘
```

### Der wichtigste Punkt: eine Engine, zwei Orte

`engine/` bekommt eine Effektbeschreibung und eine Zeitangabe und zeichnet damit auf eine
Zeichenfläche. **Genau diese Dateien laufen in der Vorschau und werden in den Export
eingebettet.** Nicht nachgebaut — dieselben Dateien.

Die Engine darf deshalb nichts über die App wissen: kein Zugriff auf das Dateisystem,
keine Node-Aufrufe, keine Oberflächen-Elemente. Sie bekommt ein Dokument mit fertigen
Daten hinein und zeichnet. Diese Grenze ist die wichtigste im ganzen Projekt; wenn sie
aufweicht, lässt sich der Effekt nicht mehr exportieren.

## 4. Die Effektbeschreibung

Ein Effekt ist ein JSON-Dokument. Das ist zugleich das Projektformat zum Speichern und
das, was in den Export eingebettet wird.

```jsonc
{
  "version": 1,
  "name": "Bergabend",
  "description": "...",
  "publisher": "Max",

  "layers": [
    {
      "id": "a1", "type": "image", "name": "Bergfoto",
      "visible": true, "opacity": 1.0, "blend": "normal",
      "asset": "img_1",
      "fit": "cover",                       // cover | stretch | contain
      "offset": { "x": 0, "y": 0 },         // Bildausschnitt verschieben
      "motion": { "kind": "warp", "speed": 15, "amount": 30 }
    }
  ],

  "controls": [
    {
      "property": "tempo", "label": { "de": "Tempo", "en": "Speed" },
      "type": "number", "min": 1, "max": 100, "default": 15,
      "bind": ["a1.motion.speed"]           // ein Regler kann mehrere Werte steuern
    }
  ],

  "assets": {
    "img_1": { "kind": "image", "mime": "image/png", "data": "…base64…" },
    "vid_1": { "kind": "video", "mime": "video/webm", "file": "bergabend.webm" }
  }
}
```

Ein Asset hat entweder `data` (eingebettet) **oder** `file` (Nachbardatei im
Effektordner), nie beides. Welcher Weg genommen wird, entscheidet die Größe — siehe
Abschnitt 6.

### Regler sind Teil des Entwurfs, nicht nur des Exports

`controls` ist der Grund, warum das Werkzeug mehr ist als ein einmaliger Umwandler: Man
legt fest, **welche Werte später in SignalRGB als Regler auftauchen.** Max stellt einen
Effekt einmal zusammen und dreht danach in SignalRGB an Tempo, Stärke und Helligkeit,
ohne SignalForge zu öffnen. Ein Regler kann auf mehrere Ebenen gleichzeitig wirken.

Beschriftungen liegen zweisprachig vor; beim Export wird die Sprache eingesetzt, die
gerade eingestellt ist. **Regler-Beschriftungen werden auf ASCII beschränkt** — wie
SignalRGB Umlaute darstellt, ist ungeprüft, und ein kaputtes „Stärke" im fremden
Programm kann man nicht mehr reparieren.

## 5. Ebenentypen

Ebenen stapeln sich von unten nach oben, jede mit Deckkraft und Mischmodus. Erlaubt sind
genau die fünf, die die Zeichenfläche von Haus aus kann (also praktisch kostenlos):

| im Dokument | Zeichenfläche | Wirkung |
|---|---|---|
| `normal` | `source-over` | deckt darunterliegendes ab |
| `add` | `lighter` | Farben addieren sich, wird heller |
| `multiply` | `multiply` | Farben multiplizieren sich, wird dunkler |
| `screen` | `screen` | weiches Aufhellen |
| `lighten` | `lighten` | je Pixel der hellere Wert gewinnt |

| Typ | Stufe | Einstellungen |
|---|---|---|
| **image** | 1 | Ausschnitt (füllen/strecken/einpassen), Verschiebung, Bewegung, Tempo, Stärke |
| **video** | 2 | Modus (Schleife/Durchlauf), Ausschnitt, Abspieltempo |
| **gradient** | 3 | linear oder radial, Farbstopps, Winkel, langsame Bewegung |
| **shapes** | 4 | Rechteck, Ellipse, Dreieck, Vieleck, freie Form; Position, Größe, Drehung, Farbe/Verlauf, Animation |

Die vier Bewegungsarten der Bildebene, damit sie nicht verwechselt werden:

| `motion.kind` | Was passiert |
|---|---|
| `none` | nichts, Standbild |
| `warp` | das Bild wird in sich verzogen — jede Stelle wandert ein paar Pixel, die Formen fließen. Farben bleiben unverändert. (Das aus dem Prototyp.) |
| `drift` | das ganze Bild wandert langsam als Ganzes über die Fläche, ohne sich zu verformen |
| `breathe` | das Bild bleibt stehen und wird langsam heller und dunkler |

`warp` und `drift` lassen sich kombinieren, indem man zwei Bildebenen übereinanderlegt —
ein eigener Kombinationsmodus wird nicht gebaut.

Neue Ebenentypen sind reine Erweiterung: eine Datei in `engine/layers/`, ein Eintrag in
der Auswahlliste. Nichts Bestehendes muss dafür angefasst werden.

### Rechenleistung

Der Effekt läuft rund um die Uhr, deshalb ist Sparsamkeit eine Anforderung, kein Extra.

- Zusammengesetzt wird bei voller Auflösung (320 × 200), damit Formen und Text scharf bleiben.
- Die teure Verzerrungsrechnung der Bildebene läuft intern bei halber Kantenlänge
  (160 × 100) und wird weich hochgezogen. Bei unscharfen Bildern sieht man das nicht.
  (Gemessen am Prototyp: 1,58 ms pro Bild ohne Grafikkarte.)
- Bildrate auf 30/s begrenzt.
- Ebenen ohne Bewegung werden zwischengespeichert und nicht jedes Bild neu gezeichnet.
- **Die App zeigt die gemessene Rechenzeit pro Bild an**, umgerechnet in „Anteil eines
  Prozessorkerns" — das versteht man ohne Nachdenken. Bei 30 Bildern/s entspricht
  1 ms genau 3 % eines Kerns. Gewarnt wird ab **5 ms (15 %)**. Zum Vergleich: der
  Prototyp von heute liegt bei 1,58 ms, also knapp 5 %.

## 6. Video

**Import:** beliebiges Format → ffmpeg → **WebM/VP9**, Breite auf ~480 begrenzt.
VP9, weil manche Chromium-Bauten kein H.264 enthalten; WebM läuft immer.

**Zwei Modi:**
- *Nahtlose Schleife* — Anfangs- und Endzeit werden gewählt, die Enden werden ineinander
  überblendet. Läuft ewig ohne sichtbaren Sprung.
- *Durchlauf* — der ganze Clip läuft und beginnt von vorn.

**Ablage:** unter 8 MB wird das Video in die HTML-Datei eingebettet (ein Effekt = eine
Datei). Darüber landet es als eigene Datei neben der HTML im Effektordner, die HTML
verweist relativ darauf. Der Export sagt an, welcher Weg genommen wurde.

**ffmpeg wird nicht mitgeliefert.** Die App sucht es in dieser Reihenfolge: eigener
Programmordner → `PATH` → bekannte WinGet-Pfade. Fehlt es, wird es **erst beim ersten
Video-Import** angeboten und mit Fortschrittsanzeige heruntergeladen. Wer nur Bilder und
Formen nutzt, braucht es nie. Das hält den Installer klein; unter GPLv3 wäre Mitliefern
erlaubt und bleibt als spätere Möglichkeit offen.

---

## 7. Export

1. Dokument einsammeln, Bilder/Videos als Daten-URI oder Nachbardatei auflösen
2. `<meta property="…">` aus `controls` erzeugen
3. Engine-Dateien und Dokument in eine Vorlage einsetzen
4. Kleines Startstück anhängen, das die SignalRGB-Variablen auf die Werte im Dokument
   überträgt und die Zeichenschleife startet
5. In den Effektordner schreiben

Bestehende Dateien werden **nicht stillschweigend überschrieben** — es wird gefragt.

## 8. Oberfläche

Ein Fenster, drei Spalten, keine versteckten Menüs:

```
┌────────────┬──────────────────────────────┬──────────────┐
│ Ebenen     │  Vorschau                    │ Einstellungen│
│            │  (320×200, groß dargestellt) │ der gewählten│
│ [+] Bild   │                              │ Ebene        │
│ [+] Video  │  ▶ ⏸   1,6 ms/Bild           │              │
│ ...        │                              │              │
├────────────┴──────────────────────────────┴──────────────┤
│ Name · Beschreibung · Regler   │   [In SignalRGB speichern]│
└──────────────────────────────────────────────────────────┘
```

- Die Vorschau ist echte 320 × 200 und wird vergrößert dargestellt — was man sieht, ist
  genau das, was SignalRGB später ausliest.
- Bilder und Videos werden per Ziehen-und-Fallenlassen ins Fenster gebracht.
- Der Bildausschnitt wird mit der Maus in der Vorschau verschoben.
- Glassmorphism: milchige Flächen über einem farbigen Hintergrund, weiche Ränder, Tiefe
  durch Unschärfe statt durch Linien. Muss dabei lesbar bleiben — Kontrast wird geprüft,
  nicht geschätzt.

### Erststart

Beim ersten Start sucht die App den Effektordner selbst. Geprüft wird der
Windows-Dokumente-Ordner (der zeigt korrekt auf OneDrive, wenn umgeleitet), zusätzlich
der klassische Pfad und der OneDrive-Pfad. Findet sie nichts oder mehreres, fragt sie
einmal und merkt es sich. **Nirgends im Code steht ein fester Benutzerpfad.**

---

## 9. Was bewusst nicht gebaut wird

Keine Galerie, kein Teilen-Dienst, kein Benutzerkonto. Keine Telemetrie. Keine
Audio-Reaktion in den ersten Stufen (später leicht nachrüstbar, weil die Ebenen dann
schon stehen). Keine Geräte-Sensoren. Keine Unterstützung anderer RGB-Programme.
Kein Code aus fremden Werkzeugen — deren Funktionsdokumentation darf als Ideengeber
gelesen werden, der Code nicht übernommen (beide haben keine Lizenzdatei).

## 10. Risiken

| # | Risiko | Gegenmaßnahme |
|---|---|---|
| **R1** | **Ob SignalRGB in Effekten überhaupt Video abspielt, ist unbelegt.** Weder auf GitHub noch im Forum gibt es einen einzigen solchen Effekt. | **Wegwerf-Test ganz am Anfang**, vor jeder anderen Arbeit. Ausweichweg: Video beim Import in eine Bilderfolge zerlegen (alle Einzelbilder nebeneinander in einem PNG) und durchblättern. Läuft garantiert, kostet Dateigröße, ändert an der Bedienung nichts. |
| **R2** | SignalRGB merkt neue Dateien im Effektordner möglicherweise nicht sofort. | In derselben Testrunde herausfinden und in der App ansagen („SignalRGB neu starten"). |
| **R3** | Viele Ebenen fressen Rechenleistung, der Effekt läuft dauerhaft. | Rechenzeit als Anteil eines Prozessorkerns anzeigen, ab 5 ms (15 %) warnen, ruhende Ebenen zwischenspeichern. |
| **R4** | Unsignierte `.exe` — Windows SmartScreen warnt Freunde beim ersten Start. | Im README beschreiben („Weitere Informationen → Trotzdem ausführen"). Ein Zertifikat kostet Geld; Max bevorzugt kostenlos. Bewusst hingenommen. |
| **R5** | Name **SignalForge** liegt nah an der Marke SignalRGB. | Von Max nach Hinweis so entschieden. Kein Logo und keine Farben von SignalRGB verwenden, im README klarstellen, dass keine Verbindung besteht. Bei Beschwerde umbenennen. |
| **R6** | Die Engine-Grenze weicht auf, dann lässt sich nichts mehr exportieren. | Die Engine darf nichts aus Node importieren. Ein Test prüft das automatisch. |

## 11. Stufen

Jede Stufe ist für sich benutzbar.

| Stufe | Inhalt | Ergebnis |
|---|---|---|
| **0** | Video-Machbarkeit prüfen (R1, R2) | Wissen statt Annahme. Wegwerfcode. |
| **1** | Electron-Gerüst, Effektordner-Erkennung, Engine mit Bildebene, Vorschau, Regler, Export | Ersetzt das heutige `bau.py` vollständig — mit Oberfläche. |
| **2** | Videoebene, ffmpeg-Anbindung, beide Modi | Die Funktion, die es sonst nirgends gibt. |
| **3** | Mehrere Ebenen, Mischmodi, Verlaufsebene | Der eigentliche Gewinn gegenüber allen anderen Werkzeugen. |
| **4** | Formen-Engine | Ersetzt die fremden Werkzeuge. |
| **5** | Veröffentlichung: GPLv3, englische Dokumente, Installer, GitHub-Release | Freunde und Öffentlichkeit. |

Der bestehende Prototyp (`claud/signalrgb-effekt/`) bleibt unangetastet und dient als
Referenz — dort ist die Bildverzerrung schon gemessen und funktioniert.

**Der Bauplan, der als Nächstes entsteht, deckt Stufe 0 und Stufe 1 ab.** Alles zusammen
in einen Plan zu packen wäre unehrlich: Was in Stufe 3 sinnvoll ist, hängt davon ab, wie
sich Stufe 1 anfühlt, wenn man sie zum ersten Mal bedient. Jede weitere Stufe bekommt
ihren eigenen Plan, wenn die vorige steht.
